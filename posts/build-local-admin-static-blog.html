从零做一个本地后台+静态发布的博客

这是一篇长文，用来把博客的 Markdown 渲染彻底跑一遍：标题层级、代码块、表格、
有序/无序列表、引用、行内代码、链接，以及中英混排下的排版效果。

一、为什么要做一个"本地后台 + 静态发布"的博客

大多数个人博客都卡在一个两难里：要么用动态服务（WordPress、各种 CMS），
省心但要一台服务器天天维护、还要担心被攻击；要么用纯静态（Hexo、Hugo），
安全便宜，但每次改内容都得回到命令行敲一堆命令。

这个项目想要两者的好处：编辑体验像动态站，运行成本像静态站。

做法是把系统劈成三层，边界非常清楚：

  1. content（内容层）：SQLite 数据库，定义"有哪些内容"。
  2. engine/server（引擎层）：唯一能改状态的地方，跑在你自己的机器上。
  3. export（导出层）：把当前内容渲染成纯 HTML + 一个 JSON，推到 CDN。

一句话：后台只在本地跑并独占数据库；"发布"只是把当下的内容快照渲染成文件。

二、数据流长什么样

   浏览器(本地)                你的笔记本                   CDN(全球)
  ┌───────────┐   编辑    ┌──────────────┐   export   ┌────────────┐
  │  /admin   │ ───────▶ │  Go 服务      │ ─────────▶ │  静态文件   │
  │  表单     │          │  + SQLite    │   git push │  HTML/JSON │
  └───────────┘          └──────────────┘            └────────────┘

关键点在于：地球仪这类"看起来像动态"的东西，其实也走静态。
它在页面上通过 fetch('/api/footprints') 拉数据，而我们在导出时，
恰好把同样的内容写成一个静态文件放在 /api/footprints 这个路径下。
于是同一份前端代码，本地跑和线上跑，行为完全一致。

三、一段真实的热点代码

下面是导出时把足迹按 国家 → 省 → 城市 分组的核心逻辑（简化版）：

func GroupFootprints(fps []Footprint) []FootprintCountry {
    order := []string{}
    idx := map[string]int{}
    for _, f := range fps {
        if f.CountryCode == "" {
            continue // 空国家码直接跳过
        }
        if _, ok := idx[f.CountryCode]; !ok {
            idx[f.CountryCode] = len(order)
            order = append(order, f.CountryCode)
        }

    }

}

这里有个刻意的设计：保留"首次出现顺序"，而不是按字母排序。
因为足迹的顺序是你旅行的顺序，排序会把这个信息抹掉。

四、三个免费托管平台对比

平台 区域优势 免费额度 谁在维护
Cloudflare Pages 全球（海外快） 无限静态请求 Cloudflare
腾讯 EdgeOne 中国大陆 有免费套餐 腾讯云
Gitee Pages 中国大陆 免费（需手动点更新） 开源中国

三个一起用的好处是互为备份：任何一个挂了，另外两个照常服务。

五、踩过的坑

  • 子路径问题：Gitee Pages 站点在 user.gitee.io/仓库名/ 下，
    绝对路径的资源会 404。解决办法是引入 BASE_URL 前缀，导出时统一改写。
  • 休眠断连：本地后台服务在笔记本休眠后会被系统回收，重启一下即可。
  • 隐私：公开仓库会暴露提交邮箱，记得用一个不含公司信息的邮箱提交。

六、结论

如果你想要一个能随手在浏览器里改、又几乎零成本、国内外都能访问的个人站，
这套"本地后台 + 静态三发布"的组合是我目前找到的最舒服的平衡点。
